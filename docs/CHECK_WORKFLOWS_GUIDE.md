## Описание

`check_workflows.py` - утилита для диагностики и проверки workflows в MongoDB.

## Когда использовать

### ✅ Используйте эту утилиту для:

1. **Отладки**: Когда получаете ошибку "Workflow not found"
2. **Разработки**: Чтобы узнать, какие workflows доступны
3. **Тестирования**: Перед использованием workflow ID в запросах
4. **Мониторинга**: Для проверки состояния workflows в MongoDB
5. **Документации**: Для получения информации о структуре workflow

### ❌ НЕ используйте для:

1. Создания новых workflows (используйте `POST /workflow/save`)
2. Удаления workflows (используйте MongoDB shell или API)
3. Модификации workflows (используйте MongoDB shell или API)

## Примеры сценариев использования

### Сценарий 1: "Workflow not found" ошибка

**Проблема**: Получаете ошибку при использовании workflow ID

**Решение**:
```bash
# Шаг 1: Проверьте все доступные workflows
python check_workflows.py

# Шаг 2: Скопируйте валидный workflow ID из списка
# Например: 68dd68fe8341ae5cb6c60024

# Шаг 3: Используйте этот ID в запросах
curl -X POST http://127.0.0.1:8080/client/workflow \
  -H "Content-Type: application/json" \
  -d '{"client_session_id": "test", "client_workflow_id": "68dd68fe8341ae5cb6c60024"}'
```

### Сценарий 2: Проверка перед использованием

**Задача**: Убедиться, что workflow валидный перед его использованием

**Решение**:
```bash
# Проверяем конкретный workflow
python check_workflows.py 68dd68fe8341ae5cb6c60024

# Если видим "✅ Workflow валидный и готов к использованию!" - можно использовать
```

### Сценарий 3: Получение списка всех workflows

**Задача**: Узнать все доступные workflows и их характеристики

**Решение**:
```bash
python check_workflows.py > workflows_list.txt
cat workflows_list.txt
```

## Технические детали

### Что проверяет утилита

1. **Формат ObjectId**: Валидность MongoDB ObjectId (24 hex символа)
2. **Наличие в БД**: Существование workflow в коллекции
3. **Структура**: Наличие поля `states` и его содержимого
4. **Начальное состояние**: Ровно 1 начальное состояние
5. **Финальные состояния**: Минимум 1 финальное состояние
6. **Типы состояний**: Распределение по типам (screen, service, etc.)

### Параметры конфигурации

Утилита использует те же настройки, что и основное приложение:

- `MONGO_DB` - база данных (по умолчанию: `test`)
- `MONGO_HOST` - хост MongoDB (по умолчанию: `localhost`)
- `MONGO_PORT` - порт MongoDB (по умолчанию: `27017`)
- `STATES_MONGO_COLLECTION` - коллекция (по умолчанию: `states`)

## FAQ

**Q: Утилита показывает 0 workflows, но я знаю что они есть**
A: Проверьте настройки в `config.py`. Возможно, используется другая база данных или коллекция.

**Q: Могу ли я использовать утилиту в production?**
A: Да, утилита только читает данные и не вносит изменений.

**Q: Как часто нужно запускать утилиту?**
A: По необходимости - когда нужна диагностика или информация о workflows.

**Q: Утилита работает медленно**
A: Это нормально для больших коллекций. Используйте проверку конкретного workflow вместо просмотра всех.

## Поддержка

Если возникли проблемы:

1. Проверьте подключение к MongoDB: `mongosh`
2. Проверьте настройки в `config.py`
3. Проверьте логи приложения
4. Используйте утилиту с конкретным workflow ID для детальной диагностики
